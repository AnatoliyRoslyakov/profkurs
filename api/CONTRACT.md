# API «Профкурс»

Браузер отправляет анкету в Cloudflare Worker. Worker проверяет поля, возвращает три профессиональных направления от DeepSeek и объяснение, как их можно сочетать. Исходник обработчика — `api/worker.mjs`. Для сборки нужен также `docs/options.js`.

## Запрос

`POST /recommend` и `POST /api/recommend` принимают один и тот же запрос. Тело — JSON в UTF-8, до 4096 байт. Передайте заголовок `Content-Type: application/json`. Параметры в URL и дополнительные поля запрещены.

```typescript
{
  version: 2,
  profile: {
    status: string,
    occupation: string | null,
    ageBand: string | null,
    interests: string[],
    otherInterest: string | null,
    location: string,
    atmosphere: string,
    strength: string,
    workStyle: string,
    hoursPerWeek: number,
    months: number,
    effort: string,
    complexity: number,
    immersion: string
  }
}
```

Все ключи обязательны. Допустимые значения каждого поля, кроме `occupation` и `otherInterest`, задаёт именованный экспорт `choices` в [списках анкеты](../docs/options.js). Числа передаются числами. Для `interests` выберите до четырёх разных занятий. Список может быть пустым, если заполнено `otherInterest` (1–100 единиц UTF-16, иначе null). Подбор предлагает профессии для широкой аудитории независимо от возраста и введённого текста. `location` определяет допустимое место работы, `atmosphere` — желаемую обстановку, `workStyle` — предпочтения в общении. Для пропущенных `ageBand` и `occupation` передайте `null`. В `occupation` допустима одна строка длиной 1–80 единиц UTF-16 без крайних пробелов, управляющих и невидимых форматирующих символов. Это поле для короткого описания занятия. ФИО, контакты и идентификаторы Telegram для запроса не нужны.

## Ответ

Версия 2 возвращает объект `{directions, connection}`. В массиве ровно три разных профессии. Поля каждой — `profession` (2–80 символов), `why` (20–360), `environment` (описание рабочего дня, 15–260), `branches` (2–3 уникальных специализации по 2–100) и `firstStep` (ориентир для знакомства с профессией без задания или срока, 15–300). В `connection` (15–300) описана возможность совместить интересы. Длина измеряется в единицах UTF-16.

Старые клиенты могут отправлять `version: 1` с прежней анкетой без `otherInterest`, `location` и `atmosphere` и с 1–3 интересами. Они получают прежний объект с полями `profession`, `why`, `firstStep`.

Worker проверяет состав объекта, тип, длину, наличие кириллицы и отсутствие переносов, управляющих символов, угловых скобок, обратной кавычки и ссылок с `http://`, `https://` или `www.`. Смысл рекомендации задаёт инструкция модели. Используется `deepseek-flash` с отключённым thinking, JSON Output и пределом 2000 токенов. При пустом, обрезанном или не соответствующем схеме тексте модель получает одну повторную попытку. Общий срок обработки — 50 секунд. [API DeepSeek](https://api-docs.deepseek.com/api/create-chat-completion/) · [JSON Output](https://api-docs.deepseek.com/guides/json_mode/) · [Thinking Mode](https://api-docs.deepseek.com/guides/thinking_mode/)

Ошибки возвращают JSON вида `{"error":"Короткое сообщение на русском."}`.

- `400` — невалидный JSON или анкета, `413` — больше 4096 байт, `415` — другой тип тела.
- `403` — неподходящий источник или preflight, `404` — другой путь или параметры URL, `405` — другой метод.
- `429` — превышение лимита клиента. Заголовок `Retry-After: 60` указывает, через сколько секунд можно повторить запрос.
- `408` — тайм-аут чтения тела, `499` — клиент прервал запрос, `504` — истёк срок ожидания после приёма анкеты.
- `502` — ошибка соединения с DeepSeek, ответа провайдера или формата рекомендации. `503` — сервис не настроен, занят либо временно недоступен.

## Настройки и данные

- `DEEPSEEK_API_KEY` — секрет Worker. Авторизация у DeepSeek происходит на сервере. Worker создаёт отдельный запрос на фиксированный адрес `https://api.deepseek.com/chat/completions` с системной инструкцией и полями анкеты.
- `ALLOWED_ORIGINS` — точные HTTPS-источники через запятую. Для сайта `https://owner.github.io/project/` укажите `https://owner.github.io`. Путь репозитория в origin не входит. Браузеру нужен успешный preflight `OPTIONS` для метода `POST` и заголовка `Content-Type`. Запросы с отсутствующим, посторонним или `null` origin отклоняются. CORS ограничивает браузеры. Внешняя программа может самостоятельно выставить заголовок Origin.
- `RATE_LIMITER` — необязательная привязка Workers Rate Limiting с `simple.limit = 5` и `simple.period = 60`. Счётчик получает HMAC от сетевого адреса, вычисленный внутри Worker. Посетители за общим IP делят лимит. Без привязки один экземпляр Worker допускает пять корректных анкет от клиента за календарную минуту UTC и одновременно учитывает до 4096 ключей. Обе схемы ограничивают частоту локально. [Лимиты Cloudflare](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/)
- Для обнаружения закрытия страницы при `compatibility_date` ранее 2026-11-17 включите флаг `enable_request_signal`. Worker передаёт отмену в запрос к модели. [Совместимость Cloudflare](https://developers.cloudflare.com/workers/configuration/compatibility-flags/#enable-requestsignal-for-incoming-requests)

Worker не ведёт журналов, не записывает анкеты и рекомендации в базу и возвращает `Cache-Control: no-store`. Инфраструктура Cloudflare принимает HTTP-запрос, а DeepSeek получает содержимое отправленной анкеты, включая свободный текст. Настройки хранения и журналов этих платформ находятся вне обработчика.
